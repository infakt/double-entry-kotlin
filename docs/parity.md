# Parity with the gem's specs

Each example of the gem's specs under `reference/double_entry/spec/` and the JUnit test that ports it. A stage adds the rows of the examples it ports, excludes or leaves pending.

- `gem example`: `spec/...rb:line`, the line of the example (`it`, `specify` or `its`). An example of `shared_examples` that `it_behaves_like` uses has a row for each context that uses it, `spec/...rb:line (context)`, as `oracle/inventory.json` keys it; one that only `include_examples` uses has one row.
- `test`: `` Class.`name` ``, the test method; `Class` is relative to the package `pl.infakt.doubleentry` (`parity.ReplayTest` for a class of the harness).
- `status`: `ported` (the test exists) or `excluded` (the note says why). `pending` (a later stage ports it) was for the stages before the parity audit; no row is pending any more.

`ParityTableTest` checks that every example of the gem's specs has a row and every row an example, that every test item of `oracle/inventory.json` has a row, that no row is pending and that every ported row names a test that exists. `DeviationsTest` checks that every `X-<nn>` the table names is in `docs/deviations.md`.

Port-only tests, such as the ones pinning a deviation (`docs/deviations.md`), have no row.
